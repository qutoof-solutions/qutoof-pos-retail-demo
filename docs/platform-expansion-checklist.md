# خطة توسّع قطوف CRM

تتابع هذه القائمة المراحل التي وافق عليها مالك المنصة، مع فصل التنفيذ المحلي عن القبول والنشر. قاعدة مرحلة RBAC والمخزون هي `c20d126` على الفرع `feature/rbac-universal-inventory`؛ لا تُدمج التغييرات إلى `main` ولا تُطبق migrations على الإنتاج ضمن هذه المرحلة.

## سجل تحقق مرحلة RBAC والمخزون

- نجح `npm run typecheck` و`npm test` (**46 اختبارًا**) و`npm run test:integration` (**16 migration**) و`npm run test:inventory` (حتى `0015`) و`npm run lint`.
- نجح `npm run build` و`npm run pages:build`.
- نجح `npm run test:api` على معاينة Pages وD1 محليتين فقط: sessions فعلية اصطناعية، عزل مختار، صلاحيات الأدوار، شراء متزامن على lot واحد، idempotency للشراء/سداد المورد/فاتورة POS/دفعة POS، تعارض بصمة الطلب، رفض lot منتهي، نقل وتسوية ومنع السالب، خصم مواد الخدمة مرة واحدة عبر الموعد وQueue، وطبيب ضمن نطاق تذاكره، وحركة مخزون متزامنة لا تُخصم مرتين.
- لا يعني نجاح البناء أو الاختبارات أن الفرع منشور أو أن اختبارًا إنتاجيًا أُجري. migrations `0012–0015` محلية وغير مطبقة على D1 الإنتاج.

## مبادئ تشغيلية

- لا تستخدم بيانات إنتاج حقيقية لاختبار العزل أو ترحيل المخطط.
- لا تُطبق migrations ولا تنشر على الإنتاج ضمن هذه المرحلة؛ يلزم مراجعة منفصلة وخطة ترقية.
- لا تُدمج إلى `main` تلقائيًا؛ التغيير يبقى على فرع الميزة حتى مراجعة ودمج صريح.
- الدفع الإلكتروني الآلي والنسخ الطويل إلى R2 مؤجلان حسب قرار المالك.
- لا حذف تلقائي لبيانات طبية/مالية ولا ادعاء بإكمال EMR أو التداخلات الدوائية أو صافي الربح دون قرارات ومصادر مناسبة.
